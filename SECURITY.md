# Security Policy

## Supported versions

| Version | Supported |
|---------|-----------|
| 1.2.x   | Yes       |
| 1.1.x   | Rollback compatibility only |
| < 1.1   | No        |

## Reporting a vulnerability

Do not disclose vulnerabilities, exploit details, credentials, server
addresses or production configuration in a public issue.

Use GitHub's private vulnerability reporting for this repository:

1. open the repository's **Security** tab;
2. select **Report a vulnerability**;
3. include the affected version, impact, reproduction steps and a proposed
   mitigation when available.

If private reporting is temporarily unavailable, open a public issue that
only requests a private contact channel. Do not include sensitive technical
details in that issue.

Reports will be reviewed and coordinated privately. A public advisory and
credit to the reporter will be considered after a fix is available, unless
the reporter asks to remain anonymous.

## Scope

Security reports may cover the runner, modules, plugin discovery, report
generation, configuration handling and documented deployment process.
Operational weaknesses that exist only in a specific server configuration
should be reported to that server's operator rather than published here.
